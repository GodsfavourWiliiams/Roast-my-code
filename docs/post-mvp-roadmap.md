# 🚀 RoastBot Post-MVP Roadmap & Implementation Guide

This document outlines the critical features required for RoastBot to move from a manual "Playground" to a fully automated production application.

---

## 1. GitHub App Integration (The "Bot")
**Goal:** Transition from OAuth (User Identity) to a GitHub App (Bot Identity) to enable automated interactions.

### Why a GitHub App?
*   **Permissions:** Request specific scopes (`pull_requests:write`, `contents:read`) without asking for full account access.
*   **Webhooks:** Native support for listening to repo events without polling.
*   **Identity:** Comments appear as "RoastBot" rather than the user's personal account.

### Implementation Steps:
1.  **Register App:** Create a new GitHub App in Developer Settings.
2.  **Permissions:** Enable Read/Write access for Pull Requests and Issues.
3.  **Bot Actions:**
    *   **Post Comment:** `POST /repos/{owner}/{repo}/issues/{issue_number}/comments` with the AI's roast.
    *   **Reject PR:** `POST /repos/{owner}/{repo}/pulls/{pull_number}/reviews` with `event: REQUEST_CHANGES`.

---

## 2. Automated Webhook System
**Goal:** Listen for real-time events to trigger roasts automatically.

**Endpoint:** `POST /api/webhooks/github`

### Core Events to Handle:
*   **`pull_request.opened` / `pull_request.synchronize`**:
    *   **Action:** Trigger the AI Roast immediately on the new diff.
    *   **DB Update:** Insert new `roasts` row with `pr_number`.
    *   **Status Update:** Increment `pending_murders` count.
*   **`repository.renamed`**:
    *   **Action:** Update `full_name` and `name` in DB to prevent broken links.
*   **`repository.deleted`**:
    *   **Action:** Cascade delete the repo and its history from our DB.

### Security:
*   **Signature Verification:** Validate `X-Hub-Signature-256` using the `GITHUB_WEBHOOK_SECRET`.

---

## 3. Manual Sync & Updates
**Goal:** Allow users to force-refresh data when webhooks fail or metadata changes.

### UI Implementation:
*   Add **"Sync with GitHub"** to the `RepoCard` dropdown menu.

### Backend Logic (`sync_repo_data`):
1.  **Fetch Metadata:** Update Stars, Forks, Watchers, and Description.
2.  **Recalculate PRs:** Fetch `open_issues_count` (filtered for PRs) and update `pending_murders`.
3.  **Framework Check:** Re-read `package.json` to detect if the user migrated (e.g., React -> Next.js) and update the `framework` column.
4.  **Timestamp:** Update `updated_at`.

---

## 4. In-App Notifications System
**Goal:** Alert users about roast completions and critical repository issues within the app.

### Database Schema (`notifications` table):
```sql
create table notifications (
  id bigint generated by default as identity primary key,
  user_id uuid references auth.users not null,
  title text not null, -- e.g., "Roast Completed"
  message text not null, -- e.g., "PR #42 scored a 2/10. Ouch."
  type text check (type in ('info', 'warning', 'critical')),
  read boolean default false,
  link text, -- Deep link to the relevant page
  created_at timestamp with time zone default now()
);
```

### Features:
*   **Toast Integration:** Trigger a `sonner` toast when a notification arrives via Supabase Realtime.
*   **Notification Center:** A dropdown in the top navigation bar showing unread alerts.
*   **Settings:** Allow users to opt-out of specific notification types (managed in `user_settings`).

---

## 5. Live Updates (Realtime)
**Goal:** Make the dashboard reflect changes instantly.

### Implementation:
*   **Supabase Realtime:** Subscribe to `INSERT` and `UPDATE` on the `roasts` and `repositories` tables.
*   **Client Hook:** `useSubscription` to auto-invalidate React Query keys (`repoDetails`, `dashboardStats`) when a new roast is inserted by the webhook.

---

## 6. Database Standards (Reference)
Ensure strict adherence to **snake_case** for all database fields:

*   `pending_murders` (NOT `pendingMurders`)
*   `violations_count`
*   `critical_issues_count`
*   `survival_rate`
*   `default_branch`
*   `framework`
*   `open_prs_count` (DB column name) mapped to `pending_murders` (Application interface)
